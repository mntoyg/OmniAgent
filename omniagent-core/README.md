# omniagent-core

A native C++20, CPU-only GGUF inference runtime. It uses the **existing local**
llama.cpp checkout at commit `869034b4bb93a425ea989d30fc3d000f5a461d58`.
There is no HTTP client, server, socket code, model downloader, RPC backend,
cloud API, or dynamic backend loader in the build. No packages or model files
are fetched by CMake. The current Python/Ollama agent remains a separate runtime.

## Build offline

Supported platform: **Linux with glibc and GCC or Clang using the GNU linker**.
The secure allocator is platform-specific; Windows, macOS, and musl builds fail
at configuration/compilation instead of silently disabling memory clearing.
On Windows, use a local WSL Linux distribution with these tools already installed.

```sh
cmake -S omniagent-core -B omniagent-core/build -DCMAKE_BUILD_TYPE=Release \
  -DLLAMA_SOURCE_DIR=/absolute/path/to/local/llama.cpp
cmake --build omniagent-core/build --parallel 4
ctest --test-dir omniagent-core/build --output-on-failure
```

Without `LLAMA_SOURCE_DIR`, the build uses `../models/llama.cpp` relative to this
directory. An API fingerprint rejects incompatible llama.cpp headers. This is
an API compatibility check, not verification of the complete dependency source;
use a trusted, audited checkout of the specified revision. For a production
build without the test/fixture executables, pass `-DOMNI_BUILD_TESTS=OFF`.

Link an application with the **`omniagent_core` CMake target**, not by copying
the `.a` alone. Its interface adds the mandatory allocator object, static C++
runtime, and `free`/`realloc` linker wrapping. The runtime replaces all global
C++ delete variants and installs silent fatal-error/terminate hooks. Those changes apply **process-wide**; use a dedicated
inference process, and do not combine this target with another allocator,
another llama.cpp installation, or other overrides of the global logging hooks.

## Use

```cpp
#include <array>
#include "omniagent/local_inference_engine.hpp"
#include "omniagent/secure_memory.hpp"

omniagent::Config config;
config.context_tokens = 2048;
config.batch_tokens = 128;
config.threads = 4;
omniagent::LocalInferenceEngine engine(config);

const auto error = engine.load("/opt/models/omniagent.gguf");
if (error != omniagent::Error::none) {
    // error_message(error) returns a bounded static diagnostic.
    return;
}
std::array<char, 4096> output{};
const auto result = engine.generate("Hello", 128, output);
if (result.error == omniagent::Error::none) {
    // Consume exactly result.bytes bytes. No trailing NUL is added.
}
omniagent::secure_zero(output.data(), output.size());
engine.unload();
```

Input is a plain UTF-8 prompt. Apply the model's chat template before calling
`generate`; this core does not infer Ollama Modelfile templates. Decoding is
deterministic greedy argmax with finite-logit validation. Encoder/decoder models
are refused. Single-file GGUFs are loaded through an already-open `FILE*`, with
mmap, lazy weights, GPU offload, and MTP disabled. Quantized formats supported
by the pinned CPU llama.cpp backend can be used without a separate conversion.

The engine preallocates token and piece buffers at load. Prompt prefill is
batched; generation decodes one token per step. It reserves the requested
token budget before any decode, instead of allowing silent context truncation.
An oversized token piece/output returns `output_limit` and clears the complete
caller-provided output span. EOS and token limit have distinct stop reasons.
Generated bytes can end within a UTF-8 character when a token limit is reached.

## File and log boundary

All model/log paths must be absolute POSIX paths. Relative paths, URIs, drive
letters, backslashes, NULs, empty components, `.` and `..` are refused. Each
component is opened using `openat` with `O_NOFOLLOW`; both parent and final
symlinks are refused. Files must be regular files. Nonblocking open prevents
FIFO/device paths from blocking before their type can be checked.

Filesystem types are restricted to ext4, XFS, Btrfs, tmpfs, ramfs, and overlayfs.
NFS, SMB, FUSE, 9p, procfs and unknown types fail closed. In WSL, a model on
`/mnt/c` or `/mnt/d` is consequently refused; place weights on the distribution's
local Linux filesystem before loading. Build sources can reside on `/mnt/d`.
Administrators must ensure allowed filesystems are backed by local storage:
the kernel filesystem type cannot prove the physical provenance of a block
device. Local path validation is not a replacement for that deployment boundary.

Optional audit logs are append-only local files owned by the current UID, with
no group/world permissions and a single hard link. Records contain only an
enumerated status, byte count and token count. Prompts, responses, paths, memory
addresses, and backend exception strings never enter these records. Upstream
llama/ggml log callbacks are silenced. No log is created unless a path is supplied.
An audit write failure returns `log_io` and erases the generated output.

## Memory and concurrency contract

- `generate`, `load`, `unload`, and `loaded` serialize using one engine mutex.
  Separate engines can run concurrently. `cancel` uses an atomic flag and the
  CPU abort callback. It cancels an active request; it is not a queued command.
- `unload` requests cancellation, waits for the current operation, synchronizes
  the backend, wipes KV/recurrent memory with `llama_memory_clear(..., true)`,
  and destroys the context **before** its model. Repeated unload is safe.
- Every request, including errors and cancellation after a partial batch,
  clears KV memory, exposed logits, tokens and token-piece scratch. Remaining
  backend compute allocations are wiped when released during unload/drop.
- Global delete and wrapped free wipe the entire glibc allocation, including
  spare capacity/padding, using volatile stores and a compiler fence. Wrapped
  realloc allocates/copies and wipes the old block before freeing it; an
  allocation failure preserves the original block. CPU scratch, C++ container
  storage, backend output buffers and weights use these release paths.
- Input and successful output belong to the caller. The caller must clear its
  own copies; the engine cannot erase memory it does not own. Join users of an
  engine before destroying it, as with any C++ object.

This contract covers owned heap buffers during normal error handling and
destruction. It does not promise erasure after SIGKILL, crashes, power loss, or
OS swap/core dumps, and does not clear kernel file caches or CPU register/stack
copies. It does not provide process isolation or locked pages. Those stronger
requirements need deployment controls. Limits bound prompt bytes, output bytes,
tokens, threads, and model **file size**, not total backend peak RAM. A trusted
GGUF is required: llama.cpp may abort on a fatal internal assertion, and C++
exception handling cannot turn an abort into an error code. The fatal callback
and terminate hook exit with code 70 without printing backend text or addresses.
The host should
apply process memory limits and supervise a dedicated worker if that failure
boundary is required.

## Verification

Tests synthesize real, deterministic Llama GGUF fixtures using only Python's
standard library. The CPU backend performs real tokenization, attention, KV
updates and decode. Tests cover exact output across ten repetitions, forty
concurrent requests, EOS, limits, aborted prefill followed by successful reuse,
concurrent unload, invalid model/path/config, symlink/FIFO/log boundaries, and
audit redaction. Secure-heap tests inspect the entire allocation **before** the
real free, including padding, realloc, C++ arrays and aligned delete. The test
observer is compiled only into its test executable.

The build replaces ggml's dynamic-library loader with a refusal stub;
`GGML_BACKEND_DL=OFF` alone does not disable explicit plugin loads in this
revision. A local test-only shared-library probe verifies that neither engine
initialization nor an explicit `ggml_backend_load` can execute a plugin,
including when `GGML_BACKEND_PATH` is set.
Another test checks undefined binary imports for networking, HTTP/TLS APIs,
`dlopen` and `dlsym`. Fatal-error testing supplies a private string and an
address to ggml's abort function and verifies exit code 70 with empty output.

These fixtures prove runtime behavior; they are not a quality or performance
evaluation of the project's Qwen model.
