## The blocker — read this before writing any test

**`scripts/build_notebook.py` writes the notebook at import time.** Lines
490–491 are at module level with no `if __name__ == "__main__":` guard, and
`OUT` on line 12 is a path relative to the current working directory.

So a test that imports the generator **overwrites the real notebook and then
compares the file to itself, and passes forever.** Fix the module first.

## Step 1 — make the generator importable and reproducible

In `scripts/build_notebook.py`:

- Add `def cell_id(index: int, source: list[str]) -> str:` returning the first
  8 hex characters of the sha256 of `f"{index}:{''.join(source)}"`. The index is
  part of the input so two identical cells cannot collide. Eight hex characters
  satisfy the nbformat id pattern. **Deterministic, never random** — a random id
  churns 24 lines of diff on every regeneration and makes the comparison test
  worthless.
- Add `def build_notebook() -> dict[str, object]:` returning the whole notebook
  dict with an `id` on every cell. **It performs no file I/O** and returns an
  equal dict on every call.
- Resolve `OUT` from `__file__` rather than from the working directory, so the
  generator writes the same path wherever it is run from.
- Move the `mkdir`, the `write_text` and the `print` under
  `if __name__ == "__main__":`. **Importing the module must touch no file.**
- Delete `import json` from the manifest cell's source text. **Keep** the
  generator's own `import json` on line 9; `json.dumps` still writes the file.
- The module docstring claims that writing the notebook as a script "lets the
  cell sources be linted like any other file". They are triple-quoted string
  literals and no linter reads them — that is how the unused import survived.
  Correct the sentence.

`mypy` is strict and this file is in scope, so both new functions need full
annotations.

## The one thing that would make all of this wrong

A test that regenerates the notebook on disk and reads it back. It compares the
file to itself, passes forever, and because the generator writes at import time
even a bare `import` does it. The whole point of this task is a check that can
fail; a check that cannot fail is what you are replacing.

The second way: replacing the deleted test with another snippet list. If your
new test contains a list of things to look for, it is the old test with a new
name. It is an equality check over the whole document or it is nothing.
